# BD Validation Script - Arctic Task - 2026-04-29

## Purpose

Run a short, repeatable validation session with trusted BD-adjacent users to test whether the app helps them form a faster and more defensible engagement recommendation.

The product wedge being tested is:

Mission Area / Use Case -> top targets -> why now -> evidence and confidence -> gaps and tradeoffs -> saved Working List.

## Setup

- Use authenticated Supabase mode.
- Start at `/app`.
- Use Arctic Domain Awareness as the first demo path.
- Do not narrate the interface unless the participant is blocked.
- Ask the participant to think aloud.
- Record where terminology, navigation, rank signal, evidence posture, or Working Lists create confusion.

## Timed Task

Give the participant 10 minutes.

1. Start from `/app` and choose the correct entry path for a mission problem.
2. Open `Arctic Domain Awareness`.
3. Explain what decision the Mission Area supports.
4. Open the briefing.
5. Compare the top 3 targets using why now, evidence posture, main risk, and suggested next step.
6. Name one gap or caveat they would disclose in a BD conversation.
7. Save at least one target to a Working List.
8. Add or review status, owner, next step, due date, and rationale.

## Debrief Questions

- Could you explain the top targets without opening every capability profile?
- Did the rank signal feel understandable as relative prioritization rather than probability?
- Did evidence posture and freshness increase or reduce trust?
- Were the gaps helpful, or did they make the recommendation feel weaker than expected?
- Would the Working List help someone else understand what to do next?
- What would you want next: outreach prep, challenge design, leadership briefing export, supplier discovery, or monitoring?

## Pass Criteria

- Participant can choose the right Start Here path without coaching.
- Participant can explain Mission Area vs Technical Domain vs Capability in plain language.
- Participant can compare the top 3 targets in under 3 minutes once on the briefing page.
- Participant understands that Derived Reads are not source-backed facts by themselves.
- Participant saves a Working List item with enough rationale for another user to continue.

## Stop Criteria

Pause broader BD rollout if participants cannot:

- Find the Arctic briefing from `/app`.
- Understand why one target ranks above another.
- Tell what is evidence-backed versus derived.
- Use the Working List without treating it as a CRM pipeline.
