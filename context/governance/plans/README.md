# Governance Plan Records

Status: active process reference
Owner: Andrew Davies
Last reviewed: 2026-09-05

Routine tasks use the completion response defined in the Codex Workflow Contract; they do not create handoff files.

Create `plans/active/YYYY-MM-DD-outcome.md` only when work genuinely spans multiple sessions and the plan must coordinate durable state. Record its owner, current outcome, source-of-truth links, completed work, open decisions, validation, and next safe action. Do not copy credentials, raw provider output, screenshots, or temporary paths into it.

When the outcome is complete, move the plan to `plans/completed/` in the same scoped governance commit. A completed plan is historical context, not a competing operating contract. Delete abandoned empty scaffolds rather than leaving placeholder plans.

Queued proposals are not adopted requirements. Historical approvals do not authorize resumption, and completed experiments are not enduring dependencies. Record the current next action and distinguish implemented, locally verified, deployed and awaiting decision; age or missing links alone do not close a plan.
